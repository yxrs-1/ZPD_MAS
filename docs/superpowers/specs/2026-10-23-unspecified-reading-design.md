# 未指定读法

教师在需求或文字里可以不写题目类型和数量。模型把「读法」交回为一个词时，核对接受这份交回并创建未发布任务。这不算失败。

文字生成和确认共用这一套核对。提示词、失败句和页面不改。测试不调用监听，不打开浏览器，也不访问网络。

## 核对

交回仍是只有「读法」「目标」「题目」的对象。「读法」去掉两端空白后还有内容时，单选、多选、判断、综合都由模型决定，题数照交回保留。四类合起来至少一道。

「读法」仍是单选、多选、判断、综合四个键时，规则不变。写明的数量必须一致，没写的类照交回保留。

「读法」去掉两端空白后是空的、目标为空、维度不是四类之一、表述去掉两端空白后为空，或一道能用的题目都没有，仍然整份拒绝。页面仍显示「生成失败，没有创建任务」，不创建任务。

目标多出别的字段时，只要维度和表述合格，就收下。某一道题目选项不够、答案对不上或写不成题目时，丢掉这一道，其余题目仍用来创建任务。解析可以空着。参考答案写成一个词时，按一项答案收下。

## 测试

测试把 JSON 字符串交给现有的题目核对。

- 「读法」去掉两端空白后还有内容，并带有一道合格综合题时，核对得到这道题。
- 「读法」去掉两端空白后是空的，或四种题都是空数组时，仍然拒绝。
- 目标多出字段、其中一道单选只有一个选项、另一道综合题合格时，核对只得到这道综合题。
- 单选的参考答案写成一个词、解析为空时，这道题仍留下，解析是空的。
