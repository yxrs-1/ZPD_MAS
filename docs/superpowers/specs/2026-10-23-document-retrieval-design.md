# 文档检索生成

高中信息科技课里，教师上传 docx 或 pdf，形成文档库。教师在目标页提交一段需求后，模型先给出检索词，应用在文档片段里查找，再由模型写出教学目标。教师改完并确认后，系统按改过的目标和这次提交的需求生成一份未发布任务。本规格描述文档库、目标页上的这次会话，以及确认后的出题。

决策智能体和支架智能体不读文档库。文字生成页不读文档库，仍按原来的规则工作。会话和这次写出的教学目标不写入文件。教师未登录时的规则不变。测试不调用监听，不打开浏览器，也不访问网络。

## 服务和数据流

课堂服务持有一份文档库，取代按字段存放的教材课时和现行课标。教师页不再按版本、册次、课时或学段检索，也不再保存、修改或删除教学目标，也不再按已保存的目标生成任务。文字生成仍使用现有入口，不写课时来源或学段来源。

一份文档有编号、原文件名和按顺序排列的片段。编号按上传顺序是 `doc-1`、`doc-2`，只增不减；删除不改其余文档的编号。docx 用标准库读取正文段落和段落样式，不另加 docx 库。表格里的段落也读取。图片忽略。pdf 用 pypdf 只提取文字，按行排列。扩展名不区分大小写，只接受 docx 和 pdf。

切分只在标题处进行，不按字数切开。docx 中，样式名是 `Heading1`、`Heading2`、`Heading3`、`Heading 1`、`Heading 2`、`Heading 3`、`标题1`、`标题2`、`标题3`、`标题 1`、`标题 2`、`标题 3` 的段落，都是标题。docx 和 pdf 里，去掉两端空白后，第一个半角或全角空白之前的文字以「第」开头、以「章」或「节」结尾，并且中间至少有一个字符，这样的单独段落或单独一行也是标题。例如「第一章」「第一章 数据与计算」「第一节 信息」。「这一章讲数据」和中间没有字的「第章」都不切分。标题和它后面的正文属于同一片段，直到下一个标题。第一个标题之前若还有正文，这段正文单独作为一个片段。没有任何标题时，全文是一个片段。片段之间不重叠。空白片段丢掉。

`classroom.json` 增加 `next_document` 和 `documents`。每份文档记下 `doc_id`、`name` 和 `chunks`。没有 `documents` 时文档库为空。读取时忽略 `lessons`、`standards` 和 `objectives`。保存时 `lessons` 和 `standards` 是空数组，`objectives` 里的课时列表和学段列表也是空的，不把读到的旧记录写回去。上传成功和删除成功后写入文件。生成目标不写入文件。确认成功后只新增任务。写入失败仍按课堂已有规则显示「没有写入文件」，内存与文件恢复一致。

教师提交需求后，第一次补全的用户消息是去掉两端空白后的需求。模型必须交回仅有一个键「检索」的 JSON 对象，值是非空字符串。检索词再去掉两端空白，按空白和标点拆开；连续的非空白、非标点算一个词。标点包含中英文逗号、句号、叹号、问号、顿号、分号、冒号和括号。一个词都没有就不再查找。否则在片段里做词面匹配：片段原文包含这个词即命中，不改变大小写。命中的不同词越多越靠前；一样多时按上传顺序，再按片段顺序。最多交回 5 段。

第二次补全不再接受新的检索。有命中时，用户消息是「教师需求：」、去掉两端空白后的需求、空行、「匹配片段：」，然后每段先写「文件名：」紧接文件名，换行后写片段原文。段与段之间空一行。没有命中时，用户消息是「教师需求：」、去掉两端空白后的需求、空行、「没有匹配内容」。模型必须交回仅有一个键「目标」的 JSON 对象。目标是数组，至少一条。每条只有「维度」和「表述」，都是字符串。维度只能是信息意识、计算思维、数字化学习与创新、信息社会责任。表述去掉两端空白后还有内容。同一维度可以有多条。这次若交回检索词，不再查找。生成目标这一步最多两次补全。

确认不再检索，最多一次补全。用户消息是「教师需求：」、这次提交并去掉两端空白后的需求、空行、「目标：」，然后每条目标两行，先是「维度：」紧接维度，再是「表述：」紧接表述，两条之间空一行。这里不追加「没有指定题型和数量。」。交回沿用文字生成已有的读法、目标和题目核对。需求里写明的题型和数量必须照做；没写的由模型决定。读法去掉两端空白后还有内容时，四种都按没写接受，并创建任务。核对通过后创建一份未发布任务，不写课时来源或学段来源。交回里的目标只用于核对，不写入目标库。成功时响应就是这份任务的任务页。

## 页面和路径

目标页仍是 `/objectives`。教师列表上的「目标」仍指向这里。课堂里地址带 `/teacher`，单独调用教师页时不带前缀。末尾多一个斜杠或查询字符串不影响。动作放在字段 `action` 里。

用 GET 打开时，按上传顺序列出已有文件名。上传字段是 `file`，`action` 是「上传」。需求文字框的名字是 `text`，`action` 是「生成目标」。旁边的「生成」仍指向 `/generation`，只打开文字生成页，不提交目标页里的内容。这时没有目标文字，也没有「确认」。

上传的文件是字节。正式运行从 multipart 读取 `file`。上传成功后仍停在这一页，新文件出现在列表末尾，不调用模型。每份文件旁有「删除」，`action` 是「删除」，字段是 `doc_id`。删除后这份文件和它的片段消失，其余文件的编号和顺序不变。

「生成目标」成功后仍停在这一页。`text` 留下提交的原文。下面是可编辑文字框 `objectives`：每条目标两行，先是「维度：」紧接维度，再是「表述：」紧接表述，两条之间空一行。按钮是「确认」，`action` 也是「确认」，同时提交 `text` 和 `objectives`。页面不显示检索到的片段。

确认成功时，这次响应就是现有的未发布任务页。之后的修改、发布和删除都按任务页已有的规则。

这一页不再有课时或学段查询，也没有查看、提炼、修改表述、删除目标和按已保存目标生成。学生地址 `/student/objectives` 仍显示「任务不存在」，状态是 404，不显示文件名、需求或目标。页面上的文件名、需求和目标都按文字写入。HTML 用拼接，不用 `str.format`。

## 失败

这些失败都停在目标页，状态是 200。文档库、已有任务和目标库保持原样。

上传时，没有文件，或扩展名不是 docx、pdf，显示「只接受 docx 或 pdf」，不读取。文件打不开、正文提取失败，显示「不能读取这份文件」。能打开但去掉空白后没有正文，显示「这份文件没有可用的正文」。这三种都不入库。

「生成目标」时，需求去掉两端空白后为空，显示「先填写需求」，不调用模型。第一次补全没有交回仅含非空「检索」的对象，或拆开后一个词都没有，显示「没有写出目标」，不查找。第二次补全没有交回仅含合格「目标」的对象，或模型调用失败，也显示「没有写出目标」。第二次即使交回检索词，也不再查找。失败后文字框留下需求原文，页面上没有目标文字，也没有「确认」。

「确认」时，需求去掉两端空白后为空，显示「先填写需求」，不调用模型。`objectives` 不能按空行分成条目，某一条不是「维度：」和「表述：」两行，维度不是那四类之一，或表述去掉两端空白后为空，显示「目标格式不正确」，不调用模型。没有文字生成记录、模型调用失败，或交回不能按文字生成已有规则接受，显示「生成失败，没有创建任务」。确认失败后，需求原文和教师改过的目标文字都留在页面上。不创建任务。

删除时，`doc_id` 对不上已有文档，显示「文档不存在」，文档库不变。不认识的动作不上传、不检索、不生成，页面只显示文档列表和空的需求框，不另报一句失败。

## 测试

测试调用教师页和课堂的处理函数，并传入临时文件。模型交回由测试事先写好。测试自己做一个最小的 docx 和一个最小的 pdf，不访问网络。测试可以直接传入文件字节。测试不调用监听，也不打开浏览器。

下面这些必须成立：

- 教师列表仍有「目标」。用 GET 打开目标页时，按上传顺序列出文件名，有 `file` 和「上传」，有 `text` 和「生成目标」，并有指向文字生成页的「生成」。没有目标文字，没有「确认」，也不调用模型。课堂里这些地址以 `/teacher` 开头，单独调用教师页时不带前缀。
- docx 按约定的标题样式，以及单独成段的「第…章」「第…节」切分。pdf 按单独成行的「第…章」「第…节」切分。标题和后面的正文在同一片段里，直到下一个标题。第一个标题前的正文单独成段。一段超过 400 字也不再切开。没有这些标题时，全文是一个片段。上传成功后仍停在目标页，新文件在列表末尾，编号是 `doc-1`、`doc-2`，不调用模型。文件名和片段写入 `classroom.json`，重新加载后还在。删除过的编号不会被下一份文件复用。
- 扩展名不是 docx 或 pdf，显示「只接受 docx 或 pdf」。文件打不开，显示「不能读取这份文件」。能打开但没有正文，显示「这份文件没有可用的正文」。三种都不入库，已有文档不变。
- 删除提交 `doc_id` 后，这份文件和它的片段消失，其余文件的编号和顺序不变。对不上的 `doc_id` 显示「文档不存在」，文档库不变。
- 「生成目标」先收到检索词，再按词面匹配。命中的不同词越多越靠前；一样多时按上传顺序和片段顺序。最多 5 段，每段带文件名和原文，并出现在第二次补全的用户消息里。页面不显示片段。目标写成可编辑的「维度：」「表述：」，两条之间空一行，并出现「确认」。需求原文留在 `text` 里。这一步最多两次补全。
- 没有任何词命中时，第二次补全的用户消息只有原始需求和「没有匹配内容」，并仍写出目标。这次交回若是检索词，也不再查找。
- 需求为空白时显示「先填写需求」，不调用模型。第一次交回不是仅含非空「检索」的对象、拆开后没有词、第二次没有合格目标、维度不是四类之一、表述为空白，或补全失败，都显示「没有写出目标」，状态是 200。文字框留下需求，没有目标文字，也没有「确认」。文档库和已有任务不变。
- 「确认」不再检索。补全的用户消息里有改过的目标和这次的需求，没有「没有指定题型和数量。」。写明的题型和数量必须一致，没写的按交回保留。读法去掉两端空白后还有内容时也创建未发布任务。成功时响应是未发布任务页，任务列表里有这份任务。它不带课时来源或学段来源。目标库没有新目标。交回里的目标不留下。会话不写入文件，重新打开目标页时没有上次的需求或目标。
- 确认时需求为空，显示「先填写需求」，不调用模型。目标文字读不出来、维度不合格或表述为空白，显示「目标格式不正确」，不调用模型。没有文字生成记录、补全失败，或题目不能按文字生成的规则接受，显示「生成失败，没有创建任务」。失败后需求和改过的目标都还在，不创建任务。
- 文件名、需求或目标里的 `<` 按文字显示。不认识的动作不上传、不检索、不生成，也不另报失败。学生地址 `/student/objectives` 仍是「任务不存在」，状态是 404。
- 文字生成仍按原规则创建任务，不读取文档库。学生求助也不读取文档库。文件里原有的 `lessons`、`standards` 和 `objectives` 被忽略；再次保存时这三项是空的，旧记录不写回。
