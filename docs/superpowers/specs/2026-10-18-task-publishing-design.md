# 任务发布

高中信息科技课里，教师编写并发布任务，学生在发布后的任务里作答。本规格描述任务条目、题目、发布和学生提交。任务生成、知识库和教学目标不在这里。

支架的六类、求助交接、HTML 四类内容和导出，仍按支架闭环规格。本规格改的是闭环打开的任务，以及提交之后页面如何锁定。

## 任务条目

系统在教师创建任务时分配标识，之后不变。每份任务单独保存自己的题目配置、学生端数据和上下文。

系统保存三项事实：是否已发布、学生是否已开始、学生是否已提交。学生端的执行状态只由这三项显示出来：已发布且尚未提交时显示待办，已提交时显示已完成。教师不填写执行状态。后端按上述三项事实处理，不读取待办或已完成这两个展示名称。

学生还没进入任务时，教师可以修改或删除它。学生端看不到未发布的任务。

## 题目

一份任务按顺序包含若干道题。题型和数量在创建时确定。暂时有三类。

- **选择题。** 题目、单选或多选、至少两个互不相同且非空的选项、参考答案、解析。题目和解析都不能为空。单选的参考答案是其中一个选项。多选的参考答案至少包含一个选项，且每一项都在选项里。
- **判断题。** 题目、参考答案、解析。题目和解析都不能为空。参考答案是「正确」或「错误」。
- **综合题。** 题目、作答要求，两者都不能为空。参考答案和解析可以空着。学生用一段文字作答，没有选项。

每道题的作答单独存放，并保留修改前的内容。闭环一次读取整份任务的全部作答。

不合格的题目会被拒绝，原配置保持不变。一道题都没有时，学生不能开始。学生作答也不合格时会被拒绝，原作答保持不变：单选要么空着，要么是一个选项；多选里的每一项都必须是选项；判断题只能空着，或填「正确」「错误」；综合题是一段文字，可以空着。

## 发布与作答

教师发布之后，学生端才看得到这份任务，并可以进入作答。此时展示为待办。发布之后、学生还没开始时，教师仍可以改配置。

学生进入这份任务开始作答时，系统建立该任务的学生端数据。仅仅出现在待办列表里，不算开始。从开始起，教师不能再改这份任务，只能删除。删除时，该任务及其学生端数据一并删除。

开始之后、提交之前，学生可以修改任何一题。作答有变化时，记下改之前的内容，并重新生成预设提问。已有的支架留在页面上。作答可以为空，学生仍然可以求助，也可以提交。

提交前，学生页面显示题目、选项或作答要求、该题作答和预设提问。求助成功后，页面再加上支架。待办列表里也不显示参考答案和解析。这两项供这份任务的两个智能体读取，学生要等提交才在该任务页面上看到。

求助针对整份任务。学生点一条预设提问，或自己写一句，决策智能体读取这份任务的题目、参考答案、解析、全部作答和行为记录，从六类支架中选一类。学情说明留在它内部。支架智能体收到这个类型、提问原话、这份任务的题目、参考答案、解析和全部作答。它不读取行为记录，也不接收学情说明。两个智能体都读不到其他任务的数据。

学生没写提问，也没点预设提问，这次不调用两个智能体。类型不在六类之中、调用失败或支架为空时，保留已有支架、预设提问和已有上下文。

## 提交

学生成功提交后，系统同时做两件事：

- 该任务的作答输入变为只读，不能再改。
- 该任务的支架对话窗口关闭发送入口。不能再发起或回复对话。已有的求助和支架记录仍可查看。

页面显示提交当时的题目、作答、参考答案和解析。综合题没填的参考答案或解析，页面上就是空的。展示状态改为已完成。提交后再改作答或再求助，都会被拒绝，页面停在提交时的结果。

## 测试

下面这些必须成立：

- 教师发布后，学生端才看得到这份任务，并可以作答。未发布的任务不出现在学生端。已发布且未提交时显示待办，提交后显示已完成。教师不能填写这两项，后端也不读取这两个展示名称。
- 每份任务有自己的标识和题目配置。学生能看到已发布的每一份。这份任务的两个智能体只读取它自己的题目、参考答案、解析、作答和上下文，读不到其他任务的数据。
- 选择题、判断题、综合题按本规格的字段保存。不合格的题目或作答会被拒绝，原内容保持不变。没有题目的任务，学生不能开始。
- 已发布、学生还没开始时，教师可以改配置。学生开始作答后，修改会被拒绝，只能删除。删除后，这份任务和学生端数据都没有了。
- 提交前，学生页面有每题作答和预设提问，没有参考答案和解析。求助成功后才出现支架。
- 成功提交后，作答输入只读，对话窗口不能再发起或回复，已有对话记录仍可查看。页面停在提交当时的题目、作答、参考答案和解析。
- 没写提问、类型不在六类之中、调用失败或支架为空时，已有支架、预设提问和已有上下文都保留。提交后再改作答或再求助会被拒绝。

任务生成、知识库和教学目标不在这次测试里。
