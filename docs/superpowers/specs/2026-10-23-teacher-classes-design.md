# 班级和学生账号

高中信息科技课里，教师登录后管理班级和学生账号，把已发布的任务布置给班级。学生登录后只作答布置给自己班级的任务。教师可以点开一名学生，查看这名学生自己的作答。本规格描述登录、班级、批量导入、布置、按学生分开的作答，以及这些内容如何写入本机文件。

教材和课标不在这里上传，也不在这里预置。文件会保存知识库和教学目标里已经有的内容。发布、草稿、提炼、生成、作答、求助和支架的原有规则保持不变，只是作答改记在登录后的这名学生名下，学生只能打开已布置给自己班级的任务。测试不调用监听，不打开浏览器，也不访问网络。

## 服务和数据流

课堂服务启动时读取当前目录下的 `classroom.json`。测试传入另一份临时文件。文件不存在就新建，并写入教师账号 `643590872`、密码 `643590872`。这份 UTF-8 JSON 保存教师页和学生页用到的内容：教师密码、班级、学生账号、任务、草稿、教学目标、知识库、布置，以及每名学生的作答、求助、支架和停留时间。一次修改成功后，先写成临时文件再换上，避免只留下半份。修改失败则不写文件。登录标记只在这次进程里有效，下次启动要重新登录。密码按原文存在这份文件里。

班级有名称和标识。标识按创建顺序是 `class-1`、`class-2`。名称去掉两端空白后不能为空，也不能和已有班级相同。一名学生有账号、密码和姓名。账号去掉两端空白后在这份服务里唯一，并且只属于一个班级。学生的作答不再记在任务上，而记在「这名学生加上这份任务」上。任务本身保留题目和是否已发布。任务页上的「已开始」表示至少有一名学生已经开始这份任务。是否已提交写在这名学生自己的作答上。

任务发布之后，教师在任务页把它布置给一个或几个班级。未发布的任务不能布置。已经布置过的班级再布置一次，结果不变。有任何一名学生开始这份任务之后，题目不能再改，教师只能删除；这份任务仍可以布置给还没布置的班级。删除任务时，布置和所有学生在这份任务上的作答一起去掉。

取消某个班级的布置后，这个班的学生不能再看到或继续作答。这些学生在这份任务上已经留下的作答从文件里去掉。其他班不受影响。一个班级都不选就提交布置，等于取消全部分配。删除班级时，班里的学生账号、他们的全部作答，以及这个班的布置一起去掉。任务本身还在。

学生登录后，只能看到已发布、并且布置给自己班级的任务。打开一份任务只开始这名学生自己的作答。教师在班级里查看详情时只读，不会替学生开始任务。学生提交之后，任务页仍显示「已开始」。

## 页面和路径

课堂入口 `/` 仍显示「课堂」，以及「教师」「学生」两个链接。登录不放在这一页。

教师还没登录时，打开任何教师地址都只显示登录。字段名是 `account` 和 `password`，按钮是「登录」，提交到这一边的 `/login`。登录成功后进入任务列表。响应设置名为 `teacher` 的 Cookie，值是这次进程里的登录标记。任务列表在「目标」旁边增加「班级」。列表上可以修改密码，字段名是 `old_password` 和 `password`，按钮是「修改密码」。账号仍是 `643590872`。列表上有「退出」，退出后清除这个 Cookie，回到登录。

「班级」打开班级列表，地址是 `/classes`。这里填写字段 `name` 并提交「创建」，创建和这份列表的提交地址都是 `/classes`。创建成功后进入这个班级。班级按创建顺序排列。班级页的地址是 `/classes/<班级标识>`。它列出本班学生，每名显示姓名和账号，顺序是加入顺序。页面提供「删除班级」，删除和导入都提交到这个班级页。删除后回到班级列表。页面上传 Excel，文件字段名是 `file`，按钮是「导入」。表是 xlsx，只读第一个工作表，第一行必须是「账号」「密码」「姓名」。只读取这三列，多出来的列不使用。账号、密码和姓名先去掉两端空白。导入后仍停在这个班级：新学生出现在名单里，不能导入的行单独列出并写明原因。

点一名学生进入详情，地址是 `/classes/<班级标识>/students/<账号>`。账号写入路径时按路径转义。修改姓名、重置密码和移除都提交到这个详情页。这里可以填写 `name` 并「修改姓名」，填写 `password` 并「重置密码」，也可以「移除」。移除后回到这个班级，名单里没有这名学生。详情列出已经布置给这个班级的每份任务，并标明「还没作答」「待办」或「已完成」。点进一份任务的地址是 `/classes/<班级标识>/students/<账号>/tasks/<任务标识>`。按题目显示这名学生的作答、参考答案、解析、历次求助和支架，并显示停留的秒数。教师在这里就看得到参考答案和解析，不论学生是否已经提交。学生自己的页面仍是提交之后才显示。这份详情只读，不替学生作答或求助。支架仍显示文字和四类素材，地址在教师前缀下。

修改密码和退出都提交到教师任务列表。任务发布后，任务页列出全部班级，每个班级一个名为 `class_id` 的选择框，已经布置的处于选中。「布置」提交到这份任务页。这次提交后，选中的班级就是这份任务的全部布置；原先选中、这次没选的班级取消布置。未发布的任务不显示这些选择框。布置的是目录里已经发布的题目。

学生还没登录时，任何学生地址都只显示登录。字段同样是 `account` 和 `password`，按钮是「登录」，提交到学生这一边的 `/login`。登录成功后进入这名学生的待办。响应设置名为 `student` 的 Cookie。待办只列出已发布、并且布置给自己班级的任务。还没打开的任务也列在待办里，状态是「待办」；提交后是「已完成」。打开后才开始。学生页有「退出」，提交到学生待办。

课堂里这些地址以 `/teacher` 或 `/student` 开头。单独调用教师页或学生页时不带前缀。末尾多一个斜杠或查询字符串不影响。上传的 Excel 是文件字节，不按普通文本表单解析。页面上出现的原文、姓名、账号、题目和标识都按文字写进页面。HTML 用拼接，不用 `str.format`。

## 失败

教师或学生登录时，账号或密码不对、账号不存在，或用对方的账号去登录，都停在登录页，状态是 200，显示「账号或密码不正确」，不发登录标记。登录标记缺失、对不上，或属于另一边时，同样只显示这一边的登录页，状态是 200。页面上没有任务、班级、学生、作答、参考答案或解析。

教师修改密码时，原密码不对，显示「原密码不正确」。新密码去掉两端空白后为空，显示「密码不能为空」。两种情况都不修改密码。修改成功后仍停在任务列表，显示「密码已修改」。

创建班级时，名称去掉两端空白后为空，显示「先填写班级名称」。名称与已有班级相同，显示「已有同名班级」。两种情况都不创建班级。

导入时，文件缺失、不是 xlsx，或第一个工作表读不出来，整份不导入，显示「不能读取这份表格」。第一行不是「账号」「密码」「姓名」，整份不导入，显示「表头必须是账号、密码、姓名」。这两种情况下已有学生不变。

表头正确时，空行跳过。合格的新账号导入当前班级。不能导入的行留在页面上，并写明原因：

- 缺账号、密码或姓名
- 账号或密码为空
- 姓名为空
- 账号在这份表里重复
- 账号已经存在

同一账号在表里出现多次时，第一次出现按上面的规则处理，后面几次都算「账号在这份表里重复」。已有账号的密码和姓名不被覆盖，也不换班级。

修改姓名时，姓名去掉两端空白后为空，显示「姓名不能为空」，原姓名不变。重置密码时，密码去掉两端空白后为空，显示「密码不能为空」，原密码不变。成功重置后仍停在这名学生的详情，显示「密码已重置」，页面上不留下新密码。

打开不存在的班级，显示「班级不存在」，状态是 404。打开不存在的学生，或学生不属于这个班级，显示「学生不存在」，状态是 404。教师查看一份没有布置给这个班级的任务，或学生打开一份未发布、未布置、或不存在的任务，都显示「任务不存在」，状态是 404。这些页面不显示题目、作答、参考答案或解析，也不开始这名学生的作答。

未发布的任务收到布置请求时，不布置，显示「先发布再布置」。布置里带有不存在的班级时，这次布置不生效，已有布置和作答都不变，显示「班级不存在」，状态是 200。一个班级都不选就提交布置，等于取消全部分配，所有学生在这份任务上的作答都去掉，任务页回到「已发布」。

有学生已经开始后，再修改题目仍显示「学生已开始，只能删除」，题目不变。写入文件失败时，这次修改不生效，页面显示「没有写入文件」。内存中的内容和文件保持一致。

## 测试

- 文件不存在时会新建。教师用账号 `643590872`、密码 `643590872` 可以登录。密码不对，或用学生账号登录教师入口，都停在登录页，状态是 200，显示「账号或密码不正确」，没有登录标记，也没有任务、班级或学生。

- 原密码不对或新密码为空时，密码不变。修改成功后，用同一份文件再启动，新密码可以登录，旧密码不可以。账号仍是 `643590872`。
