# 本机启动

高中信息科技课里，教师在这台电脑上启动课堂进程。进程先确认 DeepSeek 密钥和端口，再监听本机地址。模型调用通过标准库把请求发给 DeepSeek。本规格只描述这个启动入口和发送函数。

监听地址仍是 `127.0.0.1`。决策、支架、提炼、出题和文字生成的构造不变。教师页单独的监听不变。测试不调用真正的监听，不打开浏览器，也不访问网络。

## 服务和数据流

`python -m scaffolding.classroom` 调用 `main`。不写参数时端口是 `8000`。写了一个参数时，去掉两端空白后，每一位都必须是十进制数字，数值在 `1` 到 `65535`。`0800` 是端口 `800`。参数个数不是零个或一个时，端口不正确。

密钥从 `DEEPSEEK_API_KEY` 读取。没有设置、是空字符串，或去掉两端空白后是空的，就向标准错误写出 `没有配置 DEEPSEEK_API_KEY`，返回 `1`。这时不创建课堂，也不监听。即使端口同时不正确，也只写这一句。端口不正确时向标准错误写出 `端口不正确`，返回 `1`，同样不创建课堂，也不监听。

两项都通过之后，向标准输出写出 `http://127.0.0.1:` 加上实际端口，并立即刷新。然后用 `post_json` 调用 `production_classroom`，再把得到的课堂交给现有的 `serve`。`classroom.json` 仍写在进程当前目录。以模块方式运行时，进程退出码就是 `main` 的返回值。`serve` 正常时不返回。

`post_json(url, headers, payload)` 放在现有完成函数旁边。它用标准库发送 UTF-8 的 JSON，使用调用方给的地址和请求头，超时 60 秒。正常返回时，它交回状态码和解析后的对象；正文不是 JSON 时，第二个值是 `None`。HTTP 错误状态也按这个规则交回，不再抛出。连接失败和超时继续抛出，由现有完成函数收成 `DeepSeek request failed`。测试可以换掉打开函数。

## 失败

启动失败只有两句，都写到标准错误，返回 `1`，不创建课堂，也不监听。

- 密钥没有设置、是空字符串，或去掉两端空白后是空的：`没有配置 DEEPSEEK_API_KEY`。端口同时不正确时也只写这一句。
- 参数不是零个或一个，去掉两端空白后含有非十进制数字，或数值不在 `1` 到 `65535`：`端口不正确`。带正负号、小数点或下划线都算不正确。

状态不是 200，或正文不是 JSON 时，现有完成函数收成 `DeepSeek reply has no content`。连接失败和超时收成 `DeepSeek request failed`。页面不新增失败句。教师生成失败仍是「生成失败，没有创建任务」。学生端失败仍留在当前页。

## 测试

测试直接调用 `main` 和 `post_json`，不启动子进程。模型发送由测试注入的打开函数完成。`production_classroom` 和 `serve` 换成测试替身，不创建 `classroom.json`，不监听，不打开浏览器，也不访问网络。

下面这些必须成立：

- 没设置密钥、密钥是空字符串，或去掉两端空白后是空的，标准错误是 `没有配置 DEEPSEEK_API_KEY`，返回 `1`。即使端口也写错，也只报这一句。不调用 `production_classroom`，也不调用 `serve`。
- 密钥可用且不写端口时，标准输出是 `http://127.0.0.1:8000`，`serve` 收到 `8000`。交给 `production_classroom` 的发送函数就是 `post_json`。
- `main(["8765"])` 打出 `http://127.0.0.1:8765`，`serve` 收到 `8765`。`main(["0800"])` 打出 `http://127.0.0.1:800`，`serve` 收到 `800`。
- 两个参数、空参数、`+8000`、`8000.0`、`8_000`、`0`、`65536` 或 `abc`，标准错误是 `端口不正确`，返回 `1`，不监听。
- `post_json` 把 payload 按 UTF-8 JSON 发给打开函数，带上调用方给的请求头，超时是 60 秒。打开函数交回 200 和 JSON 正文时，结果是这个状态码和解析后的对象。正文不是 JSON 时，第二个值是 `None`。打开函数交回 HTTP 错误状态时，原样交回这个状态码，不抛出。打开函数抛出连接错误时，`post_json` 不吞掉。
