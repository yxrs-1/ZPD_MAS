# 模型生成题目

高中信息科技课里，教师按已经保存的目标记录生成未发布任务。本规格只把任务生成方换成 DeepSeek。数量检查、题目排列、未发布任务和教师查看的来源记录仍按任务生成规格执行。

目标提炼方、决策智能体和支架智能体不在这里。现有题目对象的规则不改。教师发布前仍可按任务发布规格修改题目，选择题至少保留两个互不相同的非空选项。测试不访问网络。

## 组件

新增模型生成方和完成函数。`TaskGeneration` 仍接收一个生成方。已有的脚本生成方和已有测试保持不动。

**模型生成方**实现现有的 `generate(counts, objectives)`。它组两条消息，调用完成函数，把正文解析成现有的题目对象并交回。它不创建任务，不写来源记录，也不改知识库和目标库。它不读取密钥。

**完成函数**接收这两条消息，返回正文。生产使用 DeepSeek 完成函数。测试换上返回事先写好正文的函数。

DeepSeek 完成函数通过注入的发送函数向 `https://api.deepseek.com/chat/completions` 发送一次非流式请求。模型是 `deepseek-flash`。请求把 `thinking` 的 `type` 设为 `disabled`，不带 `reasoning_effort`。密钥从 `DEEPSEEK_API_KEY` 读取，放在 `Authorization` 里，形式是 `Bearer` 加上这个密钥。发送函数交回状态码和响应体。状态码是 200，且响应体里 `choices[0].message.content` 是字符串时，完成函数只把这段正文交回。密钥缺失或请求失败时，完成函数抛出下面的 `Rejected`。

一次生成仍走 `generate_lesson` 或 `generate_stage`。数量不合法、四种数量都是 0，或没有这份目标记录时，现有检查拒绝，不调用完成函数。

## 提示词

系统消息是固定说明。用户消息是这次的四种数量，以及这一份记录里每条目标的维度、表述和来源。目标按记录中的顺序排列。

来源按原来的字段写入用户消息。教材来源是版本、册次、课时、学段、页码。课标来源是名称、学段、条款号，并标明它是现行课标。目标标识不写入。教材原文、课标原文、其他目标记录和学生作答也不写入。

固定说明要求模型只回一份 JSON 对象，并写明下面的形状和题目规则。选择题的选项正好四个，互不相同，且都不能为空白。单选的参考答案是其中一个选项。多选的参考答案至少包含一个选项，且每一项都在选项里、互不相同。判断题的参考答案是「正确」或「错误」，题目和解析都不能为空白。综合题的题目和作答要求都不能为空白，参考答案和解析可以空着。空白不算已填写。

## 正文

正文去掉前后空白后，必须直接是一个 JSON 对象。四个键都在，也不能多出别的键。某一类的数量是 0 时，那个数组是空的，键仍然保留。

```json
{
  "单选": [
    {"题目": "题干", "选项": ["甲", "乙", "丙", "丁"], "参考答案": ["甲"], "解析": "原因"}
  ],
  "多选": [
    {"题目": "题干", "选项": ["甲", "乙", "丙", "丁"], "参考答案": ["甲", "丙"], "解析": "原因"}
  ],
  "判断": [
    {"题目": "题干", "参考答案": "正确", "解析": "原因"}
  ],
  "综合": [
    {"题目": "题干", "作答要求": "要求", "参考答案": "", "解析": ""}
  ]
}
```

每道题的键正好是上面这些。选项和选择题的参考答案是字符串数组。判断题的参考答案是字符串。综合题的参考答案和解析是字符串，可以是空字符串。

同一类数组里的先后，就是交回给现有流程的先后。单选数组里的题建成单选题，多选数组里的题建成多选题。单选和多选的选项必须正好四个，互不相同，去掉空白后都不为空。这一条由模型生成方检查，不写入现有题目对象。

形状和类型通过之后，才交给现有题目对象。现有题目对象再按任务发布规格检查其余规则。

## 失败

模型生成方失败时抛出任务生成的 `Rejected`。题目对象拒绝时，模型生成方也把它变成这个 `Rejected`。`TaskGeneration` 不接住它。不创建任务，不保存来源记录，已有任务保持不变。完成函数只调用一次，不重试。

下面这些都是这种失败：

- `DEEPSEEK_API_KEY` 未设置，或去掉空白后为空。这时不发送请求。
- 请求的状态码不是 200，或响应体里没有字符串形式的 `choices[0].message.content`。
- 正文去掉前后空白后不能直接解析成上面的 JSON。包在代码块里也算失败。
- 四个键多了或少了，题目的键多了或少了，或值的类型对不上。
- 单选或多选的选项不是正好四个互不相同的非空字符串。
- 现有题目对象拒绝这道题。

JSON 的形状通过，但某一类的数量与指定的不一致时，仍由现有检查拒绝。这次完成函数已经被调用过一次。不创建任务，也不保存来源记录。

## 测试

已有的脚本生成方和已有测试保持通过。新增测试不访问网络。

- 系统消息写明 JSON 的四个键、正好四个选项，以及上面的题目规则。用户消息写明四种数量，以及每条目标的维度、表述和来源。用户消息里没有目标标识，也没有教材或课标原文。
- 一段数量相符的正文交回后，创建未发布任务。题目顺序是单选、多选、判断、综合。数量为 0 的那一类不出现。同一类保持数组里的先后。课时记录保存版本、册次、课时。学段记录保存学段。这两种来源都要测到。完成函数只被调用一次。
- 密钥缺失时不发送请求。请求失败、代码块、键不对、选项不是四个、题目对象拒绝，或某一类数量不一致时，不创建任务，也不保存来源记录。已有任务保持不变。
- 数量不合法、四种都是 0，或没有这份目标记录时，完成函数不被调用。
- DeepSeek 完成函数把请求交给测试注入的发送函数。请求发往 `https://api.deepseek.com/chat/completions`，模型是 `deepseek-flash`，非流式，`thinking` 的 `type` 是 `disabled`，不带 `reasoning_effort`。密钥放在 `Authorization` 里。状态码为 200 时，它只把回复正文交回。

知识库、目标库、题目对象和 `TaskGeneration` 的现有检查不被修改。发布后的作答、求助和提交不在这次测试里。
